# 일정 배치 자동화 알고리즘 규칙

## 배치 단위

- 학년별로 독립 배치 (1학년, 2학년, 3학년 각각 처리)
- 슬롯 = 날짜 × 교시 (예: 1일차 1교시)
- 한 슬롯에 복수의 과목 배치 가능 (수강생 중복 없는 경우에 한함)

---

## 규칙 분류

### ★ 반드시 지켜야 하는 규칙 (Hard Constraints)

#### Hard 1 — 동일 슬롯 학생 중복 금지 [최우선]

같은 슬롯(날짜+교시)에 배치하는 과목들의 수강생이 단 1명이라도 겹쳐서는 안 된다.

- 지정과목(isRequired): 해당 학년 전체 학생이 응시 → 같은 학년 **모든 과목**과 충돌
- 선택과목끼리: 수강생 교집합이 1명 이상이면 충돌

> 구현: Conflict Graph + isSlotValid() 검증. 충돌 슬롯은 후보에서 완전히 제외.

#### Hard 2 — 서논술 과목 먼저 배치

서논술(isEssay) 과목은 객관식 과목보다 **반드시 먼저** 배치 대상이 된다.

배치 우선순위:
```
0순위: 지정 서논술 (isRequired + isEssay)
1순위: 선택 서논술 (isEssay)
2순위: 지정 객관식 (isRequired)
3순위: 선택 객관식
```

> 이유: 서논술 채점 시간 확보를 위해 고사 초반에 서논술 시험을 마쳐야 함.  
> 구현: 정렬 후 순서대로 배치 → 서논술이 빈 앞쪽 슬롯을 선점.

#### Hard 3 — 고사 기간 중 빈 날짜 없음

고사 기간으로 설정된 모든 날짜에 최소 1개 이상의 과목이 배치되어야 한다.

> 이유: 빈 고사일은 학사 일정 혼란 초래.  
> 구현: 빈 날짜 보너스(emptyDay = 300)를 항상 활성화. 최대 fillSlot(90) + dayFirst 합산보다 압도적으로 높아 반드시 빈 날 우선 커버.

---

### ○ 가능한 한 만족하는 규칙 (Soft Constraints)

#### Soft A — 앞쪽 날짜·교시 선호

배치 가능한 슬롯 중 날짜·교시가 이른 슬롯을 선호한다.

- `score -= dayIndex × dayFirst`
- `score -= periodIndex × periodFirst`

#### Soft B — 슬롯 채우기 우선

이미 다른 과목이 배치된 슬롯에 함께 배치하는 것을 선호한다 (교시 수 최소화).

- `score += fillSlot` (해당 슬롯에 기존 세션이 있는 경우)

#### Soft C — 3교시 연속 응시 학생 최소화

하루에 3교시 모두 시험이 있는 슬롯에 배치할 때, 3교시 연속 응시 학생 수를 최소화한다.

- `score -= 중복학생수 × triple`

#### Soft D — 대기 학생 특정일 집중

대기 학생이 발생하는 경우, 특정 날짜에 몰리도록 배치한다 (그날 전체 대기 처리 가능).

- `score += waitConc` (해당 날에 이미 대기 발생 패턴 존재 시)

---

## 전략별 가중치

| 전략 | emptyDay | dayFirst | fillSlot | triple | waitConc |
|------|----------|----------|----------|--------|----------|
| 균형 배치 | 300 | 25 | 60 | 3 | 10 |
| 3연속 최소화 | 300 | 20 | 20 | 20 | 5 |
| 대기 최소화 | 300 | 25 | 90 | 1 | 15 |

> `emptyDay`는 모든 전략에서 300 고정 — Hard 3 보장을 위해 조정 불가.

## 배치 흐름 요약

```
① Conflict Graph 구축
   - 지정과목 ↔ 모든 같은 학년 세션 = 무조건 충돌
   - 선택과목끼리 = 수강생 교집합으로 판단

② 배치 순서 정렬 (Hard 2)
   0순위: 지정 서논술 → 1순위: 선택 서논술 → 2순위: 지정 → 3순위: 선택
   같은 순위 내: conflict 수 많은 것 먼저 → 인원 많은 것 먼저

③ 슬롯 선택 (각 세션마다)
   1. 유효 슬롯 필터 (Hard 1: isSlotValid)
   2. 슬롯 스코어 계산
      - 빈 날짜면 +300 (Hard 3)
      - 앞쪽 날짜/교시일수록 점수 높음 (Soft A)
      - 기존 세션 있는 슬롯 선호 (Soft B)
      - 3연속 페널티 (Soft C)
      - 대기 집중 보너스 (Soft D)
   3. 최고 점수 슬롯에 배치
```

## 대기 학생 정의

**대기(waiting)** = 등교해 있으나 해당 교시에 시험이 없는 학생

- 고사일에는 모든 학생이 등교한 것으로 간주
- **마지막 시험 이후 교시는 하교** → 대기 아님
- 대기가 발생하는 경우:
  1. **1교시에 시험이 없고** 이후 교시에 시험이 있는 경우
  2. **교시 사이 공백**: 1교시 시험 → 2교시 없음 → 3교시 시험 (2교시 대기)

## 데이터 전제

- `session.isRequired`: 학교지정 여부 (지정과목 = 해당 학년 전체 응시)
- `session.isEssay`: 서논술 여부
- `session.studentCount`: 응시 인원
- `enrollments[]`: 수강생 목록 (선택과목 중복 판단)
- `students[]`: 전체 학생 (지정과목 = 해당 학년 전체)
- `plan.days[]`: 고사 날짜 목록
- `plan.periods[]`: 교시 목록
